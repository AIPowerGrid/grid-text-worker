# Grid Text Worker v0.3.13

One correctness fix on top of v0.3.12. Job execution, charging, den accounting
and payouts are unchanged.

## Result Signatures

Earlier releases signed each text result in a format Grid Core does not read,
so Core recorded every text job as unsigned. This release signs the same
output commitment Core computes and sends it in the field Core verifies
(`worker_sig`, an EIP-191 signature over `aipg-job:{job_id}:{result_hash}`).
The commitment covers visible text, and also reasoning and tool calls when
present.

Nothing changes for operators: the same rig signer is used, and a job whose
signature cannot be verified still settles as before. Passthrough jobs sent in
Anthropic Messages or OpenAI Responses format are not signed yet.

## Upgrade And Trust

Stop the old worker, replace only its executable/app, then restart. Keep existing
configuration and the rig signer; no new account, key or worker identity is needed.
Verify the manifest, checksums and GitHub workflow attestations. The Linux
installer installs without running the worker or collecting credentials.

Windows is unsigned and may show SmartScreen warnings. macOS is ad-hoc signed
and not notarized; Gatekeeper may require per-app approval. Bundle integrity is
checked, but it is not a verified publisher identity. Do not disable OS security
globally. The manifest discloses the platform-signing state explicitly.

## Qualification

CI verifies the hash and signature against vectors generated by Core's own
functions. All four platform builds passed their runtime checks, and the
published files match the release checksums and manifest. The release was
published on 2026-11-10 at the owner's direction before the live check below.

Live result on 2026-11-10, against production Core `0d2ee0b7`:

- A Console-approved worker running this release from source on macOS
  (Ollama, `qwen3:8b`, one connection) served three paid chat jobs at about
  04:37 UTC. All three ledger rows carry a signature Core verified against the
  worker's delegated signer. The outputs included reasoning, so the canonical
  envelope path was exercised, not only plain text.
- Before this release, 0 of 126,842 text ledger rows had a verified signature.
- The published Linux x64 binary runs on an owned two-GPU host using an
  account API key. Core recovered one consistent signer from its jobs, which
  shows the commitment matches, and stored them unsigned because that worker
  has no signer bound to its account.

## Limits

- Signatures are stored only for workers with a Console approval, which today
  means one connection. Workers using an account API key for parallel slots or
  several models sign correctly but are recorded unsigned.
- Passthrough jobs in Anthropic Messages or OpenAI Responses format are not
  signed.
- The frozen macOS, Windows and Linux ARM64 binaries were not separately
  exercised against live Core; the live signed jobs came from a source
  install of the same tagged code.
